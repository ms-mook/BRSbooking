# BRSbooking — ระบบจองเวรหน่วยเจาะเลือดเก็บสิ่งส่งตรวจและ POCT

งานห้องปฏิบัติการเวชศาสตร์ชันสูตร โรงพยาบาลศรีนครินทร์

- **หน้าเว็บ**: โฮสต์บน Vercel (`public/`): Tailwind CSS 4 + daisyUI 5, ไอคอน Lucide, ฟอนต์ Sarabun เก็บในเว็บเอง, ธีมสว่าง/มืด, รองรับ PC เต็มจอ แท็บเล็ต มือถือ (iOS/Android) และเพิ่มไว้บนหน้าจอโฮมได้
- **หลังบ้าน**: Google Apps Script (`apps-script/Code.gs`) เป็น JSON API
- **ฐานข้อมูล**: Google Sheet

```
หน้าเว็บ (Vercel) ──POST /api/gas──▶ api/gas.js (Vercel Function) ──▶ Apps Script /exec ──▶ Google Sheet
```

## ฟีเจอร์

**บุคลากร**
- หน้าเข้าสู่ระบบแบ่งครึ่งจอ: แผงข้อมูลระบบ (วันนี้ ประกาศ สถานะรอบจอง ปุ่มวิธีใช้งาน) + ฟอร์มค้นหาชื่อและกรอก PIN
- PIN 4–6 หลัก ครั้งแรกหรือหลังผู้ดูแลรีเซ็ตใช้ PIN เริ่มต้น **1234** แล้วระบบบังคับให้ตั้ง PIN ใหม่ก่อนใช้งาน ไม่พบชื่อกด "ขอเพิ่มรายชื่อ" แล้วรอผู้ดูแลอนุมัติ
- **วิธีใช้งาน** 6 ขั้นตอน เปิดได้ทั้งหน้าเข้าสู่ระบบและในระบบ บันทึกเป็นภาพ (`public/guide.png`) เพื่อส่งต่อได้
- ปฏิทินรายเดือน แสดงเวรของตัวเอง วันเสาร์-อาทิตย์ และวันหยุดราชการ หน้าแรกมีภาพรวมเวรถัดไป เวรเดือนนี้ และสถานะรอบจอง
- จองเวร: วันธรรมดาเลือกได้หลายช่วง (06:00-08:30, 08:30-12:30, 12:30-16:30, 16:30-สิ้นสุด) เสาร์-อาทิตย์เลือกได้ 1 ช่วง (06:00-11:00, 06:00-12:00, 06:00-16:00, 06:00-สิ้นสุด) และ 1 เวรต่อวัน
- **จองหลายวันพร้อมกัน**: เปิด "เลือกหลายวัน" แตะวันที่ต้องการ แล้วจองครั้งเดียว
- กันจองช่วงเวลาซ้ำในวันเดียวกัน แก้ไข/ยกเลิกเวรของตัวเองได้ หลังปิดรอบการยกเลิกบันทึกเป็น "ลาเวร" พร้อมเหตุผลในแท็บ `Leave`
- สรุปเวรของฉัน (รายเดือน / ล่วงหน้า) พิมพ์หรือ PDF ได้ และเพิ่มลงปฏิทินมือถือ (.ics) พร้อมเตือนล่วงหน้า
- แจ้งเตือนเป็น toast มุมจอ ไม่บังการใช้งาน เปลี่ยน PIN เองได้

**ผู้ดูแล** (ปุ่ม "ผู้ดูแลระบบ" ในหน้าเข้าสู่ระบบ)
- ตารางเวรรวม 3 มุมมอง: **รายการ**, **ตารางเวร** (วันที่ × ห้อง × ช่วงเวลา) และ **ยังไม่จอง**
- กรองตามช่วงวันที่ (ข้ามเดือนได้) ห้อง จุด ตำแหน่ง ช่วงเวลา ชื่อ และรายการซ้ำซ้อน (บนมือถือตัวกรองพับเก็บได้) แล้ว Export Excel / พิมพ์ PDF ตามตัวกรอง
- เพิ่ม/แก้ไขการจองแทนบุคลากร ลบ หรือบันทึกเป็นลาเวร ตรวจพบการจองซ้ำซ้อนพร้อมป้าย "ซ้ำ"
- จัดการบุคลากร: อนุมัติคำขอ เพิ่ม แก้ชื่อ/ตำแหน่ง (ปรับชื่อในรายการจองเดิมให้อัตโนมัติ) ระงับ รีเซ็ต PIN (กลับเป็น 1234)
- วันหยุดราชการ: ดึงจากปฏิทินวันหยุดไทยของ Google (ตรวจแล้วกดบันทึก) เพิ่ม/แก้/ลบเองได้ และตั้งให้ปิดรับจองในวันหยุดได้
- ตั้งค่า: เปิด/ปิดรับจอง วันปิดรับอัตโนมัติ เดือนที่เปิดให้จอง ข้อความประกาศ เบอร์ติดต่อ กติกาวันหยุดราชการ
- **ล้างข้อมูลเก่า**: ย้ายรายการจอง/ลาที่เก่ากว่าวันที่เลือกไปแท็บ `Archive Booking` / `Archive Leave` (ไม่ลบทิ้ง นับจำนวนให้ดูและยืนยันก่อนย้าย) แนะนำทำทุก 2 เดือน

ตำแหน่งบุคลากรกำหนดที่ `CONFIG.POSITIONS` ใน `Code.gs` จุดเดียว หน้าเว็บดึงไปแสดงใน dropdown เอง

## แท็บใน Google Sheet

| แท็บ | เนื้อหา |
|---|---|
| `Booking Data` | รายการจอง คอลัมน์ A–L ตามระบบเดิม + M `ID` |
| `Leave` | ลา/ยกเลิก คอลัมน์ A–L + `ID`, `ประเภท`, `เหตุผล`, `ดำเนินการโดย` |
| `Staff` | รายชื่อบุคลากร ตำแหน่ง สถานะ PIN (เก็บเป็น hash) ไม่มี PIN = ใช้ 1234 |
| `Holidays` | วันหยุดราชการ |
| `Settings` | การตั้งค่าระบบ (แก้จากหน้าผู้ดูแล) |
| `Archive Booking`, `Archive Leave` | สร้างเมื่อกด "ล้างข้อมูลเก่า" ครั้งแรก |

> ⚠️ ติดตั้งและทดสอบกับ **สำเนา** ของชีตเสมอ อย่าผูกกับชีตที่ระบบเดิมใช้งานอยู่จนกว่าจะพร้อมย้ายจริง

## ติดตั้ง

### 1) Apps Script (หลังบ้าน)
1. เปิด Google Sheet ฉบับสำเนา → **ส่วนขยาย → Apps Script**
2. วางเนื้อหาจาก `apps-script/Code.gs` ทับโค้ดตัวอย่าง
3. **การตั้งค่าโปรเจกต์ (⚙)** → ติ๊ก "แสดงไฟล์ Manifest appsscript.json" → วางเนื้อหาจาก `apps-script/appsscript.json` (มีสิทธิ์ชีตและอ่านปฏิทินวันหยุด)
4. **พร็อพเพอร์ตี้ของสคริปต์**: `ADMIN_USER`, `ADMIN_PASS` (ยาวและเดายาก), `API_SECRET` (ข้อความสุ่ม ตั้งค่าเดียวกันบน Vercel)
5. เลือกฟังก์ชัน `setup` → **เรียกใช้** → อนุญาตสิทธิ์ ดูบันทึกการดำเนินการว่า "ปฏิทินวันหยุดไทย: พร้อมใช้"
6. **ทำให้ใช้งานได้ → การทำให้ใช้งานได้รายการใหม่ → เว็บแอป** (ดำเนินการในฐานะ: ฉัน / ผู้มีสิทธิ์เข้าถึง: ทุกคน) แล้วคัดลอกลิงก์ `/exec`

### 2) Vercel (หน้าเว็บ)
1. Import `tm-tmn/BRSbooking` (Framework Preset: **Other** — build และ output ตั้งไว้ใน `vercel.json` แล้ว)
2. Environment Variables: `GAS_URL` = ลิงก์ `/exec`, `API_SECRET` = ค่าเดียวกับ Script Properties
3. Deploy (แก้ Environment Variables ภายหลังต้อง Redeploy)

### อัปเดตโค้ดหลังบ้าน
วางโค้ดใหม่ใน Apps Script → **ทำให้ใช้งานได้ → จัดการการทำให้ใช้งานได้ → ✏️ → เวอร์ชัน: เวอร์ชันใหม่ → ทำให้ใช้งานได้**
(ลิงก์ `/exec` เดิมใช้ต่อได้ อย่ากด "การทำให้ใช้งานได้รายการใหม่" เพราะลิงก์จะเปลี่ยน)

## ความปลอดภัย
- PIN เก็บเป็น SHA-256 + salt ต่อคน (หลายรอบ) ไม่เก็บ PIN จริง และไม่รับ PIN เดาง่าย (1234, 0000, 1212 ฯลฯ)
- PIN เริ่มต้น 1234 (`CONFIG.DEFAULT_PIN`) ใช้ได้เฉพาะบัญชีที่ยังไม่ตั้ง PIN หรือถูกรีเซ็ต เข้าแล้วจอง/ยกเลิกไม่ได้จนกว่าจะตั้ง PIN ใหม่ (server บังคับ) ควรให้ทุกคนตั้ง PIN ของตัวเองโดยเร็ว ผู้ดูแลดูได้จากป้าย "PIN เริ่มต้น"
- ใส่ PIN ผิด 5 ครั้ง ล็อกบัญชีนั้น 15 นาที ล็อกซ้ำเวลาเพิ่มเป็นเท่าตัว (สูงสุด 6 ชั่วโมง) รีเซ็ต PIN ปลดล็อกให้ด้วย
- Session อายุ 6 ชั่วโมง เปลี่ยน/รีเซ็ต PIN หรือระงับบัญชีแล้ว session เดิมใช้ไม่ได้ทันที
- เรียกได้เฉพาะฟังก์ชันในรายการ `API_` ข้อมูลที่ขึ้นต้นด้วย `= + - @` บันทึกเป็นข้อความ (กันสูตรแทรก)
- Content-Security-Policy ไม่อนุญาต script ภายนอก/inline, X-Frame-Options, HSTS (ตั้งใน `vercel.json`)
- รหัสผู้ดูแลอยู่ใน Script Properties เท่านั้น ไม่มีในโค้ด/GitHub

## พัฒนาและทดสอบบนเครื่อง
```bash
npm install
npm run dev     # http://localhost:3000 ใช้ Apps Script จำลอง + ข้อมูลตัวอย่าง (ผู้ดูแล admin / admin1234)
npm run build   # สร้าง public/app.css จาก src/styles.css
npm test        # build + ทดสอบหลังบ้าน (เวลา UTC และไทย) + หน้าเว็บ (PC, iPhone SE, Pixel 7, iPad mini)
node dev/make-guide.mjs   # สร้างภาพวิธีใช้งาน public/guide.png ใหม่ หลังแก้ public/guide.js
GAS_URL=https://script.google.com/macros/s/.../exec npm run dev   # ต่อ Apps Script จริง
```

```

public/        index.html, app.js, guide.js, theme.js, config.js, app.css,
               favicon.ico, guide.png, manifest.webmanifest, icons/, fonts/, vendor/

test/          api.test.mjs, e2e.mjs, run-all.mjs
.github/workflows/test.yml                         รันชุดทดสอบทุกครั้งที่ push
```

## การทดสอบก่อน deploy
ทุกครั้งที่ push ขึ้น GitHub จะรันชุดทดสอบทั้งหมดอัตโนมัติ (แท็บ Actions) บัคที่เคยแก้มีชุดทดสอบเฉพาะ (`[R1]`–`[R32]`) กันไม่ให้กลับมาอีก
แนะนำให้เปิด Vercel → Settings → Git → **Deployment Checks** ให้รอผลทดสอบผ่านก่อนขึ้น Production
